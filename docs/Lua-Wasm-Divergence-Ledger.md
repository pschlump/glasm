# Lua→Wasm Divergence Ledger

Companion to `docs/Lua-Wasm-Design-and-Test-Plan.md` §8.9.

**Rule: a divergence without a ledger row is a bug; a row without a test is a bug.**

Where the engines disagree (or any engine disagrees with C Lua 5.1, the
semantic authority), the ruling lives here. Rows record: what diverges,
why, the ruling, and the covering test or shim.

## M6d rows (2026-09-16 — memory cap + deadline)

| # | Divergence | Where | Notes |
|---|---|---|---|
| 36 | **Alloc-cap surface (D3):** the runtime's `lua_Alloc` is `rt_alloc` (rt_abi.c; `lnewstate` builds states with `lua_newstate(rt_alloc, NULL)`), budget-checked against the init-time `rt_set_memlimit(bytes)` — a host call made BEFORE lnewstate so the whole VM lifetime (state, stdlib, shims, constant pool, script) counts. A refused allocation flows through stock 5.1's `LUA_ERRMEM` machinery as the bare literal `not enough memory` (MEMERRMSG, no position — seterrorobj's shape) — an ordinary pcall-catchable Lua error, never a trap. Two engine-side wrinkles: (i) **ERRMEM staging** — stock `luaD_seterrorobj` only runs at pcall-family recoveries, so a plain `rawrunprotected` catch (every rt_* body) would stage the stale value at `L->top-1`; `stage_c_error` stages the literal instead; (ii) **emergency slack** — while `rt_oom_inflight`, allocations up to limit+64 KiB pass so the raise's own message-interning cannot dead-end the error machinery into error handling; the counter keeps counting, so catch-and-retry gains at most 64 KiB once; `rt_err_clear`/`rt_pcall_caught`/`rt_set_state` re-arm the refusal.
